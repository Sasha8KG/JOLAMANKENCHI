# Серверная часть Cloudflare Worker

Файл `cloudflare-worker/worker.js` — подготовленная версия Worker для приложения.

## Реализованные маршруты и функции

- `GET /orders/status?id=...` — статус заказа владельцу заказа и данные назначенного водителя.
- `GET /orders/open` — открытые заказы, назначенные заказы и актуальные статусы для одобренного водителя.
- `POST /orders/respond` — отклик водителя; отказы по этому заказу исключаются.
- `POST /orders/cancel` — клиент отменяет собственный заказ до прибытия; водитель отказывается от назначенного заказа до прибытия.
- `POST /orders/arrived` — назначенный водитель отмечает прибытие. После этого отмена и отказ не разрешаются.
- `GET /dispatcher/overview` — диспетчерские данные, только для UID диспетчера.
- `POST /drivers/approve` — одобрение/отклонение водителя.
- `POST /orders/assign` — ручное назначение свободного заказа одобренному водителю с защитой от конфликтов.

При отказе водителя заказ возвращается в статус `new`; водитель, отказавшийся от заказа, больше не видит его в общем списке и не может повторно откликнуться. Таблица `order_refusals` создаётся Worker автоматически через `CREATE TABLE IF NOT EXISTS`.

## Важные правила

- Клиент может отменить заказ только в статусах `new` и `driver_assigned`.
- Водитель может отказаться только от заказа, назначенного его UID, пока статус `driver_assigned`.
- Водитель отмечает прибытие переводом заказа в `arrived`; после этого сервер отклоняет отмену клиента и отказ водителя.
- Сервер проверяет Firebase ID token и UID. Не заменяйте эти проверки клиентскими условиями интерфейса.
- Выбор ближайшего водителя: 10-секундное окно, GPS не старше 60 секунд, ближайший водитель; при равенстве — более ранний отклик.

## Финансы водителей и закрытие смен

В актуальном `worker.js` добавлены:

- `POST /drivers/commission` — диспетчер задаёт водителю долю от 0 до 100 процентов. Процент означает именно долю водителя; остаток принадлежит таксопарку.
- `POST /dispatcher/shifts/close` — закрывает дневную смену выбранного водителя. Если дата не передана, используется текущая дата Кыргызстана (UTC+6).
- `GET /dispatcher/overview` — возвращает текущие незакрытые суммы, процент водителя, доли водителя и таксопарка, а также историю закрытых смен.

Worker автоматически создаёт добавочные таблицы `driver_commission_settings`, `driver_shifts` и `shift_finance_items` через `CREATE TABLE IF NOT EXISTS`. Для уже существующих водителей первоначальный процент — 50%; ранее сохранённые значения не перезаписываются. Таблица `trip_finances` и история заказов не удаляются и не перестраиваются.

При закрытии сервер фиксирует сумму, количество поездок и процент. Повторное закрытие того же водителя за ту же дату отклоняется. Закрытые суммы не включаются повторно в текущий незакрытый заработок.

## Перед развёртыванием

1. Сохраните текущий код Worker.
2. Проверьте D1: должны существовать таблицы `drivers`, `orders`, `order_responses` и все колонки, используемые в `worker.js`.
3. Убедитесь, что привязка D1 называется `DB`, а Firebase API key соответствует проекту `jol-aman-kenchi`.
4. Разверните Worker вручную в Cloudflare и проверьте `/health`.
5. На тестовых аккаунтах проверьте клиентскую отмену, отказ водителя, повторную выдачу заказа другому водителю и отметку прибытия.

**Этот Worker Stage 9 не был опубликован в Cloudflare и не проверялся на вашей реальной D1-базе.** Архив содержит исходный код-кандидат, а не уже работающий сервер.
