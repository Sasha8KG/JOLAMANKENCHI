«ЖОЛ АМАН КЕНЧИ» ТАКСИ — ЭТАП 4

Что добавлено в исходный Flutter-проект:
1. Добавлен сетевой клиент lib/services/worker_api.dart для существующего Cloudflare Worker проекта jol-aman-kenchi.
2. Все защищённые запросы Worker подписываются действующим Firebase ID token.
3. Добавлены вызовы проверки авторизации, профиля водителя, регистрации водителя, выхода на линию, публикации/синхронизации заказов, получения открытых заказов и отклика на заказ.
4. Экран входа водителя переведён с демонстрационного PIN-кода на Firebase Email/Password с телефонным логином.
5. Добавлена отправка анкеты водителя в Worker. Новая анкета создаётся неодобренной; пока диспетчер не одобрит водителя, вход в водительский кабинет не разрешается.
6. В водительском кабинете подключена передача GPS в Worker: первое местоположение, обновления при движении и heartbeat раз в 30 секунд, пока экран водителя открыт.
7. При выходе с экрана водителя отправляется команда выключить статус «на линии».
8. Для карты выбран сервер тайлов OpenStreetMap DE, который ранее показывался в тестировании лучше стандартного адреса.

Вход водителя:
- Телефон вводится в формате 0XXXXXXXXX.
- Для нового аккаунта задаётся пароль не короче 6 символов.
- В Firebase Email/Password телефон преобразуется внутри приложения в служебный логин. Пользователю не нужно придумывать адрес электронной почты.
- Это не SMS-подтверждение номера. Реальную SMS-верификацию нужно подключать отдельным этапом.

ОГРАНИЧЕНИЯ ЭТОГО ЭТАПА — НЕ СЧИТАТЬ ГОТОВЫМИ ФУНКЦИЯМИ:
- Форма водителя пока отправляет ФИО, телефон, модель и номер автомобиля. Загрузка фотографий удостоверения/автомобиля и проверка документов ещё не подключены.
- Экран водителя пока не загружает открытые заказы из Worker в список приложения. Сетевой метод получения заказов подготовлен, но интерфейс заказов ещё нужно связать с ним.
- Принятие заказа, маршрут к пассажиру, завершение поездки, тарифы и отчёты пока не переведены полностью с демонстрационных локальных данных на сервер.
- Экран пассажира и экран диспетчера пока сохраняют демонстрационные элементы и не являются завершёнными сетевыми кабинетами.
- Голосовая рация пока не передаёт звук. Для неё потребуется отдельный голосовой канал (например, WebRTC) и сервер сигнализации.
- APK в этом окружении не собран и на телефоне не проверен. Для этого необходима совместимая установленная Flutter/Android SDK.

ВАЖНО ПЕРЕД ИСПОЛЬЗОВАНИЕМ:
- В Firebase Authentication должен быть включён метод Email/Password.
- Cloudflare Worker должен оставаться развёрнут по адресу, записанному в worker_api.dart.
- Новая анкета водителя отправляется в таблицу drivers через /drivers/register. Диспетчерское одобрение выполняется серверным endpoint /drivers/approve.
- Не выдавайте текущую сборку пассажирам и водителям как готовое коммерческое приложение.

Открытие:
1. Распакуйте архив.
2. В VS Code откройте папку testapp.
3. В терминале папки выполните flutter pub get.
4. Затем flutter analyze.
5. Для сборки APK после устранения всех ошибок: flutter build apk --release.

Если flutter analyze выдаст ошибки, сохраните весь текст и передайте его для исправления. Сам архив является исходным проектом, не готовым APK.
